# TiDB 

UDTS支持 TiDB 作为数据传输源/目标，支持版本 3.* 以上

## 迁移内容

以 TiDB 为源迁移到 MySQL/TiDB 时，目标库数据的清理行为与 MySQL 迁移一致：

- 数据源配置中的「保留目标库数据」默认开启，任务启动时不会清理目标库数据；关闭该选项后，任务启动时会清理本次迁移对应的库表。
- 开启（默认）时，目标库中已存在的表不会被删除或重建，目标库中相同主键或唯一键的数据可能导致任务报错或数据不一致，请自行清理目标库数据。
- 该选项仅在包含全量迁移的任务（全量、全量+增量）中显示；仅增量任务没有该选项，也不会清理目标库数据。

清理范围的详细说明参考 [MySQL迁移到MySQL](/udts/type/mysql_source/mysql2mysql) 或 [MySQL迁移到TiDB](/udts/type/mysql_source/mysql2tidb)。

## TiDB 填写表单

| 参数名   | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| IP       | 内网地址需要填写VPC和子网信息。                            |
| 端口     | 连接端口                                                |
| 用户名   | 连接用户名                                              |
| 密码     | 用户名对应密码                                          |
| 数据库名 | 如果是单个数据库，请填写数据库名；如果是多个数据库，填写以逗号分割的数据库列表；如果是所有数据库，请填写* |                                              |
| 表名     | 传输表名，只有迁移单个数据库时有效。如果是单个表，请填写表名；如果是多个表，填写以逗号分割的列表；若不填或者填写*，则整库迁移     |
| 保留目标库数据 | 默认开启。开启时任务启动不会清理目标库数据，可能导致任务报错或数据不一致，请自行清理目标库数据；关闭时任务启动将自动清理目标库数据，清理范围参考[迁移内容](#迁移内容) |

## 预检查项

以TiDB为源库时，TiDB参数`tikv_gc_life_time`建议大于1小时，以避免迁移过程中发生 GC 导致迁移失败。

查询方式：
```
select VARIABLE_NAME, VARIABLE_VALUE from mysql.tidb where VARIABLE_NAME = "tikv_gc_life_time"
```

设置方式：
```
set global tidb_gc_life_time = '24h';
```
